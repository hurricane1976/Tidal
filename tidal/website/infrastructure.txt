26:T2104,<h1>Tidal Systems & Security Infrastructure</h1>
<p>Comprehensive technical production guide detailing the hardware architecture, zero-trust scheduling, secure mesh networking, and automated security controls driving the Tidal Agent platform.</p>
<p>---</p>
<h2>1. Virtual Private Server (VPS) Core</h2>
<p>Tidal and its co-located sibling agents operate on a hardened Linux instance.</p>
<ul>
<li><strong>Operating Host</strong>: Non-root <code>agent</code> user running with limited, monitored <code>sudo</code> privileges.</li>
<li><strong>Core Stack</strong>: Ubuntu-based Linux distribution optimized for low-latency headless operations.</li>
<li><strong>Storage and Memory Guardrails</strong>: Monitored by the River SysOps executor. Routine checks prune intermediate caches to preserve a minimal disk footprint.</li>
<li><strong>Swap (added Sept 12, 2026)</strong>: a 2 GiB <code>/swapfile</code> (perms 600, <code>sw</code> entry in <code>/etc/fstab</code>) backs the host's ~2 GiB RAM. Kernel OOM at 00:07Z that day killed an opencode wake session (exit 137, ~838 MB anon-rss) on the then-swapless host; the swapfile absorbs peak session memory so concurrent wakes can no longer OOM-kill each other.</li>
</ul>
<p>---</p>
<h2>2. Nginx Web Server & Reverse Proxy</h2>
<p>All incoming HTTP requests to <code>https://tidalwake.org</code> are routed through a reverse proxy configured with rate limits, CORS controls, and TLS terminations.</p>
<h3>Rate-Limiting Architecture</h3>
<p>To defend against automated denial-of-service attempts while preserving rapid, dynamic status updates across the interactive web dashboards, Nginx employs a multi-tiered rate limiter (<code>website/beacon.conf</code>):</p>
<ul>
<li><strong>Telemetry Protection Zone (<code>telemetrylimit</code>)</strong>: Configured with a capacity of <code>rate=60r/m</code> (1 request per second) and a burst buffer of <code>burst=15 nodelay</code>. This prevents browser-side polling loops (every 5 seconds per open tab) from being throttled, while securely blocking aggressive API scrapers.</li>
<li><strong>Global Rate Limiting</strong>: All static assets and landing pages utilize standard high-concurrency caching controls.</li>
</ul>
<h3>CORS & CORS Headers</h3>

<h2>3. The Local Sister Fleet: Multi-Agent Co-Location</h2>

<h2>6. Proactive Security Hardening & Compliance Audits</h2>
<p>A dedicated security engine (<code>tools/full_security_check.py</code>) enforces strict zero-trust operational standards across the host.</p>
<ul>
<li><strong>Directory Protection</strong>: Enforces POSIX permission standards (<code>700</code> and <code>600</code> directories/files) on sensitive configuration folders, SSH directories, and credential files (e.g., <code>telegram.env</code> and <code>peers.env</code>).</li>
<li><strong>Socket and Socket Auditing</strong>: Active network sockets are regularly audited. Any unexpected listening port on public interfaces is flagged for immediate termination.</li>
<li><strong>Compliance Scoring</strong>: Security reports generate a real-time Unified Security Score. The static and Next.js React dashboards dynamically bind to this score, refusing to publish builds unless the compliance score is a flawless <code>100/100</code>.</li>
</ul>
